# 怎麼改成別的尺寸 / 別的物品

這份講**哪些東西會自己跟著變**、**哪些改了會失效必須重校**、**改完要重新驗哪幾項**。
只想照跑一次的話看 `README.md` 就夠了。

---

## 1. 換一個物品(不是馬克杯)

換掉 `assets/mug.stl` 就好,其餘**自動跟著算**:

| 東西 | 怎麼來的 |
|---|---|
| 物品躺平尺寸 `ME` | 讀 STL 的 bbox。單位自動判斷(最大跨距 > 1 就當 mm) |
| 物品姿態 | 腳本會把它轉成躺平(`Ry(-90) → Rx(90)`),再置中 |
| **包材尺寸** | 由 `ME` 算出來,見下面的公式 |
| 六面壓實的起始開度 | 依包材尺寸 |

包材尺寸的公式(`wrap_sim.py` 第 288~294 行,照 `wrap_plan.py`):

```
佔位塊   A, B, HC = ME + 2*margin(高度只加 1 個 margin)
折線位置 CX, CY   = A/2 + wall, B/2 + wall
爬升     climb    = hypot(wall, HC)
折邊長   FLAPX    = climb + A/2 + overlap
布邊長   WX       = A + 2*wall + 2*FLAPX
最後取   max(WX, WY) 做成正方形
```

三個可調的裕度(預設值是這條 pipeline 用的):

| 旗標 | 預設 | 意思 |
|---|---|---|
| `--margin` | 0.012 | 佔位塊比物品大多少(每邊) |
| `--wall` | 0.006 | 折線離佔位塊側面多遠 |
| `--overlap` | 0.025 | 兩片在頂面重疊多少 |

`--sheet_mm 400` 可以直接指定正方形邊長(蓋掉自動計算)。
腳本一定會印「最小需求 vs 實際採用」,**指定值小於最小需求時就包不住**,看那行就知道。

> ⚠ 換物品之後,**六面壓實的目標 `--press6 W,L,H` 要自己重訂**。
> 它不會自動算 —— 現在的 `250,210,115` 是為這個馬克杯挑的。
> 訂法:先不壓跑一次,看包裹自然的 bbox,再往下壓 10~15%。

## 2. 換紙箱尺寸

用生成器,**不要手改 USD**:

```bash
/isaac-sim/python.sh make_carton_P.py \
    --out mybox.usd --hx 0.1335 --hy 0.1135 --height 0.131 \
    --t 0.0015 --layer_gap 0.0065 --clear 0.0025
```

`hx`/`hy` 是**牆中心線**,外徑 = `2*(hx+t)`。所以 270×230 的箱子是 `hx=0.1335, hy=0.1135, t=0.0015`。

也可以用 `--config`,設定檔放 `configs/box/*.json`(命令列永遠優先)。

**自動跟著算、不用管的:**

| 衍生量 | 公式 |
|---|---|
| 內壁 `IN_X/IN_Y` | `hx - t` / `hy - t` |
| 上鉸鏈 `Z_OUT` | `height - t` |
| 下鉸鏈 `Z_IN` | `Z_OUT - layer_gap` |
| **±x 牆高** | `Z_IN - 2t` ← 讓位給下蓋板厚 |
| **±y 牆高** | `Z_OUT - 2t` ← 讓位給上蓋板厚 |
| 上蓋半寬(齊邊) | `IN_X - flush_gap` |
| 下蓋伸長 | `IN_X - 0.0015` |

全部寫進 `<name>.meta.json` 的 `derived`。**`wrap_sim.py` 一律從那裡讀,不寫死** ——
所以換箱子不用改模擬腳本。

> ⚠ 讀 meta 要讀 `wall_top_x` / `wall_top_y`。
> `wall_top_z` 現在只是 `--height` 參數本身,**不等於任何一面牆的實際高度**。

**改了會失效、必須重校的:**

| 參數 | 為什麼 |
|---|---|
| `ajar` / `ajar_in`(預抬角) | 是為 340×340×260 校的。config 自己就標了 `_INVALIDATED`。板厚/密度/摺線軟硬/尺寸任一變動都作廢 |
| `lever_arm` / `force_cap_torque_Nm_at_30N` | 力臂 = 上蓋側邊到下蓋摺線的距離。齊邊改過之後**目前是 1.0mm,而 meta 裡的力上限還是舊值**,尚未重算 |
| `--press6` 目標 | 見上一節 |

**一個幾何下限**:物品高 + 箱底板厚 + 包材兩層厚度 ≤ 箱內高。
馬克杯的例子:93 + 3 + 約 30 = 126mm,所以 100mm 的箱子**幾何上不可能**,130 才行。

## 3. 調包材的軟硬

| 旗標 | 這條 pipeline 用的值 | 說明 |
|---|---|---|
| `--young` | **2e4** | 面內楊氏模數。越大越不容易被拉長 |
| `--bend` | **4** | 抗彎。**這個是地雷,見下面** |
| `--thick` | 0.010 | `surfaceThickness`。碰撞殼是中面 ±thick/2 |
| `--solver` | 64 | position iteration。**全場景取最大值**,會污染分欄對照 |
| `--layer_mm` | 8(前兩折)/ 12(後兩折) | 每折的終點 z 分層,避免兩層布落在同一位置 |

> ⚠ **`--bend` 的預設值是 2e3,那會讓布直接睡死。**
> 實測:bend=2e3 時布在 t=0.83s 之後 16 秒 bbox 一動也不動,折疊等於沒跑。
> 這條 pipeline 用 **bend=4**。`--no_sleepy` 幫助不大,真正的原因是 bend。

碰撞容差(`wrap_sim.py` 第 190 行,不是旗標):

```python
CONT, REST = 0.005, 0.001    # contactOffset 5mm, restOffset 1mm
```

意思是:兩個碰撞體表面距離 < 5mm 就開始產生接觸,solver 會把它們推到分離 1mm。
判斷「算不算穿模」要拿這兩個數字當尺,不是拿布的厚度。

## 4. 改完要重新驗這幾項

改任何東西之後,**這些都要重跑**,不能只看畫面:

| 檢查 | 工具 | 過的標準 |
|---|---|---|
| 蓋子會不會穿箱壁 | `carton_sweep.py`(解析,純 CPU,不用 GPU) | 0~180° 全程 **0 重疊** |
| 布會不會穿物品 | `chain_pen.py`(吃 `traj.npz`) | 全程 **0 條邊** |
| 布/物品有沒有超出箱內腔 | `check_place.py` | 超出 0 個 |
| 布自己的自穿模 | `fold_pen.py` | 越低越好(目前約 1900,**未解**) |
| 布有沒有被拉長 | 跑完 log 的「是不是同一張布」 | 邊長比中位 **0.95~1.05** |
| 包材是不是真的包住 | `--lift_mug 0.20` 提杯測試 | 跟隨比 > 0.8 且全程 0 穿模 |

**只測頂點會漏。** 布穿物品必須用**邊級別**判定(每條邊取內點測是否在物品內部)——
實測過:頂點判定說 0 條、邊判定說 14 條。`chain_pen.py` 用的是邊級別。

## 5. 兩個排查用的經驗

**A/B 一定要餵同一個 `--init_npz`。**
每個中間狀態都是模擬出來的,同樣的指令重跑一次結果就不一樣。
要確認兩次比較的輸入相同,看第 0 格的 bbox —— 相同輸入的 bbox 必然相同(平移不改變 bbox 尺寸)。

**階躍 vs 漸增比絕對值有用。**
某個量在階段交界**跳一下** ⇒ 擺位/記帳問題;在階段內**慢慢爬** ⇒ 真的被物理擠出來。
這條 pipeline 的「布穿物品」曾經在入箱那一格從 0 跳到 172,就是靠這個判斷出是座標 bug
而不是包覆不良。

## 6. 續跑別人跑過的 run

**不要憑記憶拼指令。** 兩個可靠來源:

1. **影片底部的參數標籤** —— 材料參數都寫在上面(`E=2e+04 bend=4e+00 solver=64`)
2. **`out_*/wrap_sim.log` 的開頭 30 行** —— 每個被啟用的旗標都會印一行自己的訊息

反查方法:把 log 裡的某行訊息拿去 grep 腳本,就知道是哪個旗標印的。例:

| log 訊息 | 對應旗標 |
|---|---|
| `★ 後兩折抓的邊來自實測` | `--floor_edges floor_edges.json` |
| `★ 第二段:布以第一段的結果出生` | `--init_npz` |
| `★ 六面壓實:目標 ...` | `--press6 W,L,H` |
| `★ 入箱:整包(布+杯子)剛性搬 ...` | `--carton` + `--init_npz` |

漏掉 `--floor_edges` 會直接 `NameError: SIDE2 is not defined`。
