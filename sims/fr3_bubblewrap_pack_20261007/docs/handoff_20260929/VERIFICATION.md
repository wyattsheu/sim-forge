# 模型驗證 —— 整合對照

這份不是新的一套流程。**紙箱模型的驗證體系早就存在**(`overnight/CARTON_QA.md` 的 S0~S6
關卡 + `carton_lab/lab/measure/` 的量測腳本),這份的作用是:

1. 把**包材模型**的驗證接上同一套關卡與詞彙
2. 說明我這輪新寫的工具各自掛在哪一關(不是另立門戶)

## 沿用既有的判定詞彙

`qa_carton.py` 定的四種結果,包材這邊也照用:

| 結果 | 意思 |
|---|---|
| PASS | 量到的數字達標 |
| FAIL | 沒達標 |
| **VACUOUS** | **恆真,無鑑別力** —— 檢查本身沒有意義,不給 PASS |
| SKIP | 前提未達成,這一關沒測 |

★ `CARTON_QA.md` 的兩條總則同樣適用:
**「上一關沒過就往下做,失敗會偽裝成別的問題」**、
**「協議沒跑完 = 沒有測到,不是部分通過」**。

## 二、包材模型 —— 接上同一套關卡

紙箱是剛體 + 關節,包材是 surface deformable,所以關卡內容不同,但層次對應:

| 對應關卡 | 工具 | 過的標準 | 這輪 |
|---|---|---|---|
| P0 參數健檢 | `selfcheck.py` C 區 | 折序單一來源、三張衍生表不寫死、杯子旋轉 det=+1 | ✅ |
| S0 不開模擬 | `selfcheck.py` A/B 區 | 紙箱幾何、蓋子掃掠 | ✅ |
| S1 確認連結 | log 的 `S0 出生時自穿模` | 從攤平起步應為 **0**(>0 代表是我「擺」出來的) | ✅ |
| S2 確認碰撞 | `chain_pen.py` **邊級別** | 布穿物品全程 0 條 | 待量 |

| S3 確認彈性 | log 的「是不是同一張布」 | 邊長/攤平 中位 0.95~1.05 | ✅ 1.014 |
| S4 確定靜置 | bbox 時間序 | 最後數格不再變化 | ✅ |

## 三、座標方向的驗證(既有為主)

| 要驗什麼 | 工具 | 怎麼驗 |
|---|---|---|
| 紙箱每片蓋的鉸鏈位置與姿態 | `insp_carton.py` | 直接印世界座標,不推算 |
| 場景的軸向、長邊方向 | `insp_scene.py` | 印出來對 |
| 整組轉 90° 之後 x/y 對不對 | `build_full_scene.py` 內建 | 轉完自己印「x OK / y OK」 |
| 開啟角 | `verify_box.py` | ★ 用**幾何**量(蓋子遠端相對鉸鏈的高度差 ÷ 蓋長 → asin),**不用關節四元數反推** —— 那在 90° 附近會跳分支,先前害我兩次誤判「紙箱打不開」 |
| 杯口/杯耳方位 | `selfcheck.py` C 區 + 三視圖投影 | 從**網格本身**量(端面半徑比較 + 圓環斷面),不從參數推 |

## 四、這輪的實測結果

**紙箱** `carton_v2`:S0 那一項 ✅(0/361,舊箱對照 360/361)。**其餘 S1~S6 尚未用既有工具跑過。**

**包材**(折序改成 PPT 要求的 x 先):

| | 舊折序(y 先) | 新折序(x 先) |
|---|---|---|
| 布超出內腔 | 0~4 | **67**(56 低於箱底、11 穿出 y 牆) |
| 自穿模 | 1919 | **3231** |
| 邊長比中位 | 1.002 | 1.014 |

⇒ **PPT 要求的折疊順序,對這組布/杯尺寸本質上比較不利。**
x 邊較短(195 vs 208mm),先折 x 之後,較長的 y 邊要包過更高的堆疊。
這是折法的取捨,不是 bug。要改善只能調 `--layer_mm` 或加角落三角摺。
