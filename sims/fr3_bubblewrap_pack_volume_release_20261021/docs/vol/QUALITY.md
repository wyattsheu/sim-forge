# 開發用快速模式 `--quality fast|final|off`(2026-10-21)

使用者要求:「不要用那 240,用 60 就可以了解細節,只需要在最後產出那一版再把精度調高」。

## 結論
dt 1/60 試過了,不能用:四折 bbox 寬 13 mm、自穿 111、反轉 13、搬後 5 點超出內腔(quality/F1)。所以 fast 退到 **dt 1/120 + solver 48**(再加 vid_every 2、960x540)。
fast 整條鏈 wall/sim = **6.1~6.4**。同一時段、同樣負載(GPU 上另有 1 個模擬)跑 final 是 10.5,所以 fast **快 1.7 倍**;只看物理段是 4.0~4.5 對 8.1~9.6,快 **2.1 倍**。整鏈快不到 2 倍,原因是 yn/yp 抓取規劃各會停 40~160 s,這段時間跟 dt 無關。
fast 能過的判準:四折 bbox(與 final 差 ≤ 5 mm)、關蓋後 0 超出、穿杯 0、反轉 0、yn/yp 綁定與拿住、守衛不觸發、取杯出箱(t=121.55、穿杯 0)。
fast 比較差的:自穿全程最大 30~32(final 5~8)、搬前/搬後有 1~3 個布點貼底超出(≤ 0.9 mm;final 0~1 點)、關蓋後 bbox x 多 4~7 mm。

## 用法
```
# 開發 / 調參 / 看細節
/isaac-sim/python.sh wrap_vol.py <正式旗標> --quality fast  --out xxx
# 要交付的那一版(出片、報數字)
/isaac-sim/python.sh wrap_vol.py <正式旗標> --quality final --out xxx
```
| quality | dt | solver | vid_every | vid_res |
|---|---|---|---|---|
| off(預設) | 舊預設 1/240 | 128 | 1 | 1280x720 |
| fast | 1/120 | 48 | 2(影片 15 fps,播放仍是實時) | 960x540 |
| final | 1/240 | 128 | (不動,1) | (不動,1280x720) |

- 個別旗標有明確給的,以個別旗標為準。例如 `--quality fast --solver 64` 的 solver 是 64,其餘照 fast。
- log 第 3 行印 `quality: fast | dt 1/120 solver 48 vid_every 2 vid_res 960x540 | preset 套用 [...]`;渲染那行也印 quality、影片 fps、解析度;影片字幕 L2 尾巴加 `| Q fast`。
- 重跑:`quality/run.sh NAME --quality fast`(= extract4 正式旗標 + 額外旗標);`quality/run_prog.sh` 會多記每 10 s 的 sim t,`python3 quality/prof.py quality/NAME/conc.txt` 印各段倍率;`python3 quality/table.py DIR...` 產生下表。

## 只能在 final 下相信的結論
- **自穿 / 互穿數字**:fast 約是 final 的 4~6 倍(30~32 對 5~8)。SPEED.md 的 dt 1/120 也一樣(13~25)。DEMO 的「互穿 ≤ 8」只能拿 final 驗。
- **入箱 0 超出的搬前/搬後(bm/am)**:fast 有 1~3 點、≤ 0.9 mm 貼底。只有關蓋後(closed)在 fast 也是 0。
- **bbox 精確到 mm、體積÷杯**:四折 ±5 mm 內,但關蓋後 x 多 4~7 mm。
- **掀開放手後回彈、他片被拖、布被帶起 %**:這些是 run-to-run 雜訊大的量(final 自己 3+1 次就有 yn 0~99%、帶起 17~37%),fast 2 次落在 final 的範圍內,但樣本不夠下結論。SPEED.md 也記過 dt 1/120 會讓「放手後」從 62% 掉到 0%(舊旗標、沒 hold_yp)。比較兩組參數時要用 final。
- **wall/sim 倍率**:被 GPU 上其他模擬汙染(下表 conc = 同時在跑的其他模擬,平均/最大)。

fast 可以信的:流程跑不跑得完、事件時間點、綁定點數量級、守衛會不會觸發、杯子出不出得來、有沒有穿杯/反轉/NaN、四折外形。
