# 給 Isaac Sim 負責 AI：兩篇柔性物體 sim-to-real 論文的發現，以及對我們包材模擬的參考價值

## 背景（我們在做什麼、卡在哪）

我們用 Isaac Sim 5.1 的 surface deformable（PhysX 布料）把馬克杯用泡泡紙包起來 → 六面壓實 → 放進紙箱 → 關蓋。
工作目錄是 `/isaac-sim/test_scripts/manip_fr3/handoff_20260929/work/`，主程式是 `wrap_sim.py`。
目前布料參數：contactOffset 5.0 mm、restOffset 1.0 mm、surfaceThickness 4 mm、selfFilter −1（預設），布寬 400 mm，`--young 2e4 --bend 4`。

目前卡住的問題：
1. **層間距壓不下去**：每層約 4.3~5.6 mm，包裹高 122~130 mm（杯高 93）。壓到 117 mm 一放開就彈回 130~134。把 rest shape 設成壓扁的樣子還是一樣彈回去，所以撐開層與層的是自碰撞，不是彎曲。縮小 restOffset 可以讓層貼近，但會變成互穿（自穿模上千）
2. **放開後面內方向彈開**：壓住時 y=173 mm，放開後 y=250 mm，比內腔 224 mm 還大，入箱時 24 個頂點穿出 y 牆
3. 自穿模一路累加：14 → 80 → 109 → 約 280
4. 體積是杯子的 3.1 倍，真實包裝大約 1.5~2 倍

## 論文一：SimWeaver（arXiv 2606.15338）

只用模擬資料訓練 RGB VLA 策略，真機做 5 個柔性物體任務，零真實資料微調，平均成功率 91.3%。

**跟我們直接相關的發現：**

- **他們評估過 Isaac Sim 內建的 PBD 布料，結論是不能用**（論文 Fig. 2）："Isaac Sim with PBD cloth exhibits instability and fails to grasp the garment"。Newton VBD 在雙臂操作時會出現布與剛體穿模。他們最後改用自家的 RGBench solver，Omniverse Kit 只拿來渲染
  - 對我們的意義：PhysX 布料在「夾住、壓住、多層疊」這類高接觸情況本來就是弱項。我們卡住的問題 1、3 不是參數沒調好，是這個 solver 的已知限制
- **夾爪附近的「禁止碰撞區」（§3.2）**：他們在每個夾爪周圍定義一個區域，區內關掉布的自碰撞，區外保留，並要求粒子離開這個區域之前，所有交叉都要被 solver 內建的 untangling 機制解開。夾爪合起來時區域縮小，張開時放大。目的是讓多層布夾得緊又不抖動
  - 參考價值：**概念可以借，但 PhysX 沒有 untangling**。在我們這裡關掉局部自碰撞，等於讓它互穿，跟縮小 restOffset 是同一個問題。除非能找到 PhysX 裡做局部 filtering 的方法，而且放開之後層能自己分回去，否則不建議硬搬
- **布料參數是查表來的，不是調出來的**（附錄 A）：每種布料的 stretch/bend 剛性、密度、厚度、夾爪摩擦都來自工業量測的布料庫，素材綁到對應的布料類別，不逐任務調參
  - 參考價值：支持「用泡泡紙真實厚度當口徑」的做法。泡泡紙一層本來就約 3~4 mm，我們的 4.3~5.6 mm 只比真實值大一點點。報告可以寫成「模擬層厚 vs 真實泡泡紙層厚」，不必追求零厚度
- **量化穿模**：他們拿穿模率當 simulator 的品質指標。我們已經有 `chain_pen.py`（邊級別）和 `fold_pen.py`（自穿模），方向一致
- **軌跡生成（SimWeaver-Syn）**：在 mesh 上標語意點（角、邊中點），建一張「可以一起抓的點對」拓撲圖。再加上遮擋判斷（某點上方圓柱內有非鄰近點，就代表被壓住）和閉環驗證：抓完先檢查，失敗就重選
  - 參考價值：適合用在**開箱**，也就是雙臂掀泡泡紙那段：判斷哪一片在最外層、哪個角沒被壓住可以抓。我們的折序是 FOLD_ORDER，最外層是最後折的那片，這張圖可以從折序直接建出來
- **之後要訓練視覺策略才會用到的**（現在先記著）：
  - 桌高隨機只往下 −1.5→0 cm，模擬成功率從 90% 升到 97%
  - Sobol 取樣
  - 光照 ±0.7 stops、色溫 4000–6500 K
  - 影像增強關掉後，真機成功率 5 個任務**全部 0%**
  - `kit_frame_updates=1` 讓渲染延遲 40–80 ms，對齊 RealSense 的延遲

## 論文二：SIM1（arXiv 2604.08544，上海 AI Lab）

real-to-sim-to-real：少量真實示範 → 數位孿生 → 校準布料物理 → 用 diffusion 擴增軌跡。純合成資料訓練的策略可以跟真實資料打平（1:15），真機 zero-shot 成功率 90%。

**跟我們直接相關的發現：**

- **Solver**：他們用 NVIDIA Warp 寫，延伸 Newton–VBD，加上 AVBD（Augmented VBD），全部在 GPU 上跑，約 15 fps
- **Strain limit 5%（§3.2，對應問題 2）**：每條邊如果拉超過 5%，就啟動一條虛擬彈簧。剛性從 1e4 逐次往上加，最高到 1e6，再用拉格朗日乘子累積修正力。目的是在接觸過程中不讓布爆開或過度拉伸
  - 參考價值：這是針對「接觸後布彈開或變形失控」的 solver 層解法，PhysX 做不到。在 PhysX 裡能近似的是：放開前保留最外層兩片（±y）的部分 attachment、分段放開（一次放一片、每次之間 settle），或入箱後讓箱蓋代替壓板繼續壓住
- **防穿透的位移裁切（附錄 B.5，對應問題 1、3）**：每次迭代的頂點位移上限 d_safe = 0.42 × min(碰撞半徑, 到最近三角形距離, 到最近邊距離)，超過就等比例縮小。這是讓碰撞半徑可以設得小、但不會穿過去的關鍵
  - 參考價值：這正是我們「縮小 restOffset 就互穿」的對應解法，但它是 solver 內部機制。PhysX 最接近的旋鈕是開 CCD（目前 `ccd False`）、加 collision iteration（目前 colIterMult 0）、把 timestep 縮小。**這三項值得配合小 restOffset 一起試**，看互穿能不能被壓住
- **他們的校準參數（Table 2）**：
  | 參數 | 值 |
  |---|---|
  | particle radius | 0.008 m |
  | 面密度 | 2.0 kg/m² |
  | StVK μ / λ | 1e2 / 1e2 |
  | bending | 8e-4 |
  | strain limit | 5% |
  | 自碰撞摩擦 | 0.25 |
  | **自碰撞半徑** | **0.002 m（2 mm）** |
  | body-cloth margin | 0.01 m |
  - 參考價值：這是 AVBD 的參數，**單位和 PhysX 不能直接對應，不要直接填進去**。但有一個重要的參考點：**目前最好的布料 solver，自碰撞半徑也設在 2 mm**。所以「每層小於 1.5 mm」（口徑 B，薄膜）連 SIM1 都沒有做到，這可以當成跟使用者說明口徑 B 不實際的依據
- **校準方法（§3.2、附錄 B.7）**：把真機的關節狀態即時串流進模擬，讓模擬做出一樣的動作，再用肉眼比對下垂、折疊、接觸，反覆調參數。他們明講這些參數「無法直接最佳化回真實物理值」
  - 參考價值：如果手邊有真的泡泡紙，可以量一個基準，例如真實泡泡紙包好杯子後的高度、壓下去放開會彈回多少。拿來對比模擬的 117→130，就能回答「彈回 13 mm 合不合理」，不用一直追零回彈
- **紀錄格式**：每幀狀態存 NPZ，完整軌跡和接觸存 USD 方便事後檢查。我們目前已經存 npz 和 traj.npz，方向一致

## 建議你接下來做的事（照優先順序）

1. **問題 2（y 方向彈開）**，參考 SIM1 strain limit 的精神，用 PhysX 做得到的方式：
   - 用 `edge_report.py` 先確認放開後是哪一片在動
   - 試「最外層 ±y 兩片保留 attachment 到入箱」以及「分段放開」，每組報放開後 bbox 和超出內腔的頂點數
2. **問題 1（層間距）**，參考 SIM1 防穿透的精神：
   - 固定 restOffset 1.0，掃 contactOffset 5 / 3 / 2 mm
   - 再試小 restOffset 搭配 CCD on、collision iteration 加倍、timestep 減半，看互穿能不能壓住
   - 每組報層間距、放開後高度、自穿模數
3. **口徑佐證**：整理一張表，比較我們每層 4.3~5.6 mm、真實泡泡紙 3~4 mm、SIM1 自碰撞半徑 2 mm，給使用者決定口徑 A 或 B 用
4. **開箱抓取點**，參考 SimWeaver 拓撲圖：用 FOLD_ORDER 標出每一片的外層角點，並加上「上方有沒有被壓住」的判斷。等開箱段要接雙臂時再用

## 注意

- **不要自己決定換 solver**（Newton/Warp）。這是大改，要先問使用者
- 論文的數字是他們的設定量出來的，套到我們這裡都要重新量過才算數
- 每個實驗都要附數字和影片，回報用繁體中文：做了什麼 → 數字 → 影片路徑 → 下一步建議
